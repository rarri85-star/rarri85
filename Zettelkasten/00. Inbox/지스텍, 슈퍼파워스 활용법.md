바이브 코딩의 

**단계별 사용 순서**

코덱스로 아래 순서대로 지스텍과 슈퍼파워스롤 뽑고 클로드 코드로 마무리 하는 방법을 시행해봤다

1. **아이디어 입력**
    
    - 만들고 싶은 서비스/기능을 자유롭게 설명한다.
    - 대상, 기능, 참고 이미지, 원하는 화면, 포함/제외할 정보까지 넣는다.
2. **gstack office-hours 검토**
    
    - 이 아이디어가 만들 가치가 있는지 본다.
    - 사용자 문제, 시장성, 차별점, 리스크, 데이터 출처, 운영 가능성을 검토한다.
3. **핵심 사용자 선택**
    
    - 처음부터 모두를 대상으로 하지 않는다.
    - 예: 가벼운 사용자 / 파워 유저 / 특정 팀 팬 / 관리자 등으로 나눈다.
    - 첫 버전에서 가장 단순하고 자주 쓸 사용자를 고른다.
4. **MVP 범위 축소**
    
    - “전체 제품”이 아니라 “첫 번째로 만들 버전”을 정한다.
    - 반드시 뺄 기능도 함께 정한다.
    - 예: 로그인, 고급 통계, 상세 페이지, 알림 등은 후순위로 미룬다.
5. **접근안 2-3개 비교**
    
    - 최소 구현안
    - 장기적으로 좋은 구조
    - 조금 더 창의적인 대안  
        이렇게 2-3개를 비교한다.
6. **추천안 선택**
    
    - 가장 빨리 검증할 수 있고, 확장 가능한 방향을 고른다.
    - 선택 이유를 한 문장으로 정리한다.
7. **Superpowers 검증**
    
    - 선택한 방향이 너무 크지 않은지 확인한다.
    - 데이터 흐름, 화면 구조, 예외 상황, 테스트 가능성을 점검한다.
    - “지금 만들 것”과 “나중에 만들 것”을 다시 분리한다.
8. **최종 스펙 정리**
    
    - 목표
    - 핵심 사용자
    - MVP 기능
    - 제외 기능
    - 데이터 전략
    - 화면 구조
    - API 구조
    - 실패/빈 상태 처리
    - 모바일 대응  
        이 정도만 정리한다.
9. **구현 프롬프트 작성**
    
    - 코딩 AI나 개발자에게 줄 수 있는 형태로 바꾼다.
    - mock data, API 구조, 타입, 화면 구성, 검증 방법까지 포함한다.
10. **개발 단계 진입**
    
    - 바로 전체 서비스를 만들지 않는다.
    - 먼저 mock data 기반 MVP를 완성한다.
    - 이후 실제 데이터, 사용자 설정, 고급 기능을 붙인다.
      # Zettelkasten/00. Inbox/

## 목적과 역할
머릿속에 떠오른 생각, 링크, 인용구를 마찰 없이 빠르게 캡처하는 임시 보관함입니다.
완성도보다 속도가 우선입니다. 여기서 오래 머무는 노트는 없어야 합니다.

## 어떤 노트가 들어가는가
- 즉각적인 아이디어·질문·영감
- 나중에 읽을 링크나 자료
- 아직 분류되지 않은 단상
- 다른 앱(모바일 등)에서 이동해 온 빠른 메모

## 작업 방식과 규칙
- 매일 또는 주 1~2회 Inbox를 처리(Triage)
- 처리 시 각 메모를 다음 중 하나로 이동:
  - `10. Literature/` — 외부 자료 기반 메모
  - `20. Permanent/` — 자신의 아이디어로 발전된 메모
  - `Resources/` / `Projects/` / `Areas/` — 해당 영역의 자료
  - 삭제 — 더 이상 가치 없는 메모
- Inbox가 비어있는 상태를 목표로 유지 (Zero Inbox)
- 제목 앞에 날짜 prefix 불필요 (Obsidian 생성 시각으로 충분)
